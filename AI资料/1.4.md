# 仿OpenClaw

## 1.1 OpenClaw 原理 & 机制

### 1.1.1 概述

​	OpenClaw是一个本地优先，模型无关的AI智能体执行网关，作为连接大模型，通讯渠道与系统工具的中枢桥梁，给大模型装上“手脚”，让它能直接操控你的计算机，完成跨应用，跨平台的复杂自动化任务。

### 1.1.2 原理

#### 1.1.2.1 概述

OpenClaw是一个本地优先，数据主权，模型中立，插件化解耦，其底层原理围绕AI智能体的自动执行闭环与分布式网关架构展开，核心可差结尾3大核心原理。

#### 1.1.2.2 OTAC 智能体循环原理

​	这是OpenClaw 实现自主任务执行的核心算法范式，也是所有AI Agent能力的底层基础

+ 观察(Observe)：接收用户自然语言的指令，渠道消息，工具执行返回结果，系统环境状态等全量上下文信息，完成输入信息的标准化解析。
+ 思考(Thought): 将标准化的上下文传入接入的大模型，完成任务拆解，目标规划，工具选择，风险判断，核心支持ReAct(推理-行动交替)，Plan-and-Execute（先规划后执行）,Self-Ask(自我提问式推理) 3中推理模式。
+ 行动（Act）: 根据模型决策，调用对应的工具/节点能力，执行具体操作（如Shell命令、文件读写、浏览器操作、API调用等）
+ 检查（Check）：对执行结果进行校验，判断是否达成子目标，若未完成则重新进入（规划-思考-行动）循环，直至任务完成，最终像用户反馈结果。

#### 1.1.2.3 "网关+节点+渠道" 三层解耦框架原理

​	这是OpenClaw最核心的架构创新，彻底解决了传统AI Agent 交互，推理，执行紧耦合的问题。

+ 网关（Gateway）:是系统的心脏与中枢，作为唯一的控制平面，所有消息，指令，数据都先进入网关，完成路由，会话管理，权限控制，状态维护，实现“万流归宗”的统一调度。
+ 节点（Nodes）: 是系统的执行四肢，任何设备（PC、手机、NAS、云服务器）都可作为节点接入，节点向网关声明自身可提供的能力（如 Shell，浏览器，摄像头，文件系统），网关根据任务需求自动执行请求路由到对应的节点。
+ 渠道（Channels）： 是系统的交互入口，将“微信”，“飞书”,“Telegram”，等20+ 通讯平台 抽象为统一的协议，实现“任何聊天窗口都是AI的控制台”, 用户无需切换平台即可下发指令。

#### 1.1.2.4 本地记忆管理原理

​	OpenClaw 彻底摒弃了云端记忆存储，所有记忆数据完全本地化，解决了大模型上下文窗口限制与个性化持续学习的问题，核心采用三级记忆架构：

+ 工作记忆：实时会话上下文，默认存储在内存/Redis 中，TTL 为1小时，用于当前任务的连续推理
+ 短期记忆：按时间戳归档的会话历史、操作日志、存储在本地SQLite 数据库，用于近期任务回溯与上下文关联
+ 长期记忆：自动从短期记忆中提炼的用户偏好、行为习惯、经验教训、关键知识、存储在本地Markdown文件与向量数据库中，每次推理时自动召回，实现“越用越懂你”的个性化体验。

### 1.1.3 运行机制

#### 1.1.3.1 核心运行机制

​	除了核心的OTAC循环，OpenClaw的稳定运行依赖4个关键配套机制。

（1）多模型中立调度机制

​	OpenClaw 本身不训练、不提供模型、而是作为模型调度器，适配 OpenAI、Anthropic、DeepSeek、通义千问、智谱AI等几乎所有主流大模型， 支持运行时动态切换模型、故障转移、低成本模型降级、用户可完全自动控制推理成本与能力上限、无厂商锁定的风险。

（2） 心跳与定时任务机制

 这是OpenClaw 从“被动响应”到“主动服务”的核心,分为两类：

+ 心跳机制（Heartbeat）： 按固定时间间隔唤醒智能体，重新加载记忆与上下文，自动检查待办任务、状态变化、完成定时巡检、状态汇报、任务提醒等操作、实现7*24小时无人值守运行；
+ 定时任务（Cron）：支持用户配置的定时执行规则，实现周期性任务自动化（如每日数据备份、周报生成、定时消息推送）

（3）标准化工具调用与沙箱安全机制

+ 工具标准化：所有执行能力都被封装为标准化的 Skill/工具，通过统一的 Schema定义入参，出参,功能描述，大模型可自动识别并调用，支持原子操作、组合技能、工作流三级扩展，用户可以自定义开发工具；
+ 安全沙箱：高风险操作（如Shell命令，系统级调用）默认在Docker 隔离沙箱中执行，支持权限白名单/黑名单配置，可限制工具的访问范围，避免误操作导致的系统风险，同时所有操作都有完整审计日志。

（4）分布式会话与状态管理机制

​	网关层通过WebSocket 全双工通信，统一管理所有渠道，节点，会话的状态，所有会话状态、tokens的统计，执行进度都有网关唯一持有，客户端/节点不私自维护状态，避免分布式环境下的状态不一致的问你题，同时支持会话中断恢复、多设备同步。
