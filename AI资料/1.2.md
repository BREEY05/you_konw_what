# 人工智能大模型周边生态全套

覆盖： 单一对话->上下文机制->上下文缓存->提示词Prompt->函数调用Function Calling->Skills技能系统->MCP 协议->智能体Agent ->RAG知识库->插件系统->编排工作流

# 第一章 大模型原生能力（最底层：没有任何周边依赖）

## 1.1 什么是原生大模型

原生大模型： 模型出厂自带、训练完成后、不需要任何外部插件、不需要外部文件、不需要协议、纯模型本身能力

原生三大能力：

1. 文字生成
2. 简单逻辑
3. 静态知识（训练截止时间前）

## 1.2 阶段1： 最简单形态----单次独立对话（无上下文）

### 1.2.1 定义

每一句话互相独立，模型记不住上一句。

### 1.2.2 运行原理

用户发一句->模型计算->返回结果->内存全部清空

### 1.2.3 优缺点

有点：占用资源极低，速度最快，成本最低

缺点： 不能连续聊天、不能跟进任务、没有记忆

### 1.2.4 应用场景

早期智能客服，一次性问答、简单翻译

## 1.3 阶段2： 大模型基础升级----上下文对话（上下文窗口）

### 1.3.1 什么是上下文

上下文： 让模型记住本次聊天历史记录，连续理解对话

通俗：给模型装一个临时记事本

### 1.3.2 上下文窗口（Context Window）

所有大模型都有固定窗口限制：

+ 小模型:4k,8k(几千字)
+ 中端模型：32k,64k
+ 高端模型：128k，200看，1M(百万字)

### 1.3.3 上下文运行机制

1. 用户发送最新一句话；
2. 系统会把本次全部聊天记录打包 一起发给模型；
3. 模型结合历史理解；
4. 生成回答；
5. 保存在上下文队列；

### 1.3.4 致命缺点

上下文越长、费用越贵、速度越慢、容易溢出

溢出：超出最大字数，自动删除最早聊天记录

## 1.4 阶段3： 上下文优化---- 上下文缓存、压缩、切片

原生上下文弊端极大， 于是穿线周边优化以及依赖技术

1. 上下文缓存： 重复提问不重复计算,节省算力

2. 上下文压缩：把长对话精简摘要，减少token

3. 上下文切片：超长文档分段读取

4. 遗忘机制： 自动清理无用历史

   总结: 以上全部属于模型最底层基础周边，没有这些就不能正常连续对话聊天

   

# 第二章 第一层周边依赖：人机交互层（Prompt 工程体系）



## 2.1 什么是 Prompt

Prompt: 提示词，人类给模型下达的指令语言。

是人和大模型唯一沟通桥梁。

## 2.2 Prompt发展分级

L1 自然随口提问

例如：帮我写一篇作文

缺点： 模糊，质量差，随机性大

L2 结构化提示词

包含：角色+任务+要求+格式+限制

例如：你是一个资深的语文老师，写800字议论文，写一篇描写爸爸的议论文，结构总分总，语言朴实

L3 思维链Prompt （CoT）

强制模型分步思考、拆解逻辑

L4 few-shot 少样本提示

给模型示范案例，照着格式生成。

L5 高级工程级 Prompt

包含： 约束词，禁止词，输出JSON, 格式锁定，语义锁定

## 2.3 Prompt 本质地位

Prompt 是最便宜，最简单，最基础的大模型周边依赖

不需要开发，不需要部署、人人可用。

# 第三章 第二层周边依赖： 模型原生扩展（Function Calling 函数调用）

## 3.1 为什么要有 Function Calling

原生大模型缺点：

1. 不能联网
2. 不能计算实时数据
3. 不能操作外部软件
4. 不能调用接口

于是OpenAI推出： Function Calling（函数调用）

## 3.2 通俗定义

让大模型自己判断什么时候调用工具、调用什么工具、传什么参数

## 3.3 工作流程

1. 用户提问
2. 模型判断： 需要调用外部函数
3. 自动生成参数JSON
4. 调用外部接口
5. 获取结果
6. 整理成自然语言回答用户

## 3.4 常见Function

计算器，查天气，联网搜索，查询数据库，生成图片

## 3.5 定位

是大模型通向外部世界的第一道官方大门。

# 第四章： 第三层周边依赖： 标准化技能层(Skills 技能系统)

## 4.1 什么是Skills

### 4.1.1 官方定义

Skills 是模块化，标准化，可复用，可编排的**AI技能单元** ，最早由Anthropic（Claude）提出，目前所有AI编程工具，智能体全部通用。

### 4.1.2 通俗定义

Skills = 给AI写好的操作手册，工作流程，执行模版

Function 是单一工具；Skills 是一套完整做事流程。

### 4.1.3 Skills 文件结构（真实工业格式）

一个Skill 通常是一个md文件，包含：

1. 技能名称;
2. 适用场景;
3. 执行步骤;
4. 限制条件；
5. 引用代码或脚本；
6. 返回格式；

## 4.2 Skills 核心特点

1. 可复用：一次编写，永久使用；
2. 轻量化：占用上下文极低；
3. 动态加载： 不用不加载，用时在加载；
4. 可编排： 多个技能组合完成复杂任务；

## 4.3 Skills 和 Function的区别

1. Function： 单个原子工具（查时间，计算，查天气）
2. Skills: 多个工具+ 流程+规范（完整工作任务）
3. Function 偏向代码接口；Skills偏向业务流程；
4. Function 由开发者写代码; Skills 由普通人编写文档即可



## 4.4 举例

+ Function： 螺丝刀（单个工具）
+ Skills： 维修手机全套步骤手册

# 第五章 第四层周边依赖： 通信协议层（MCP协议核心）

## 5.1 MCP是什么

### 5.1.1 官方全称

MCP= Model Context Protocal 模型上下文协议

由 Anthropic 2024年底发布，目前AI行业通用工业标准。

### 5.1.2 通俗定义

**MCP是AI界的USB-C通用接口**

统一的大模型和外部所有软件、数据库、代码、文件的通信标准

## 5.2 MCP 出现之前（混乱时代）

每一个工具都要单独写一套对接代码： 

连数据库写一套，连本地文件写一套，连终端写一套, 连代码写一套

开发量大，兼容性差，无法通用

## 5.3 MCP 出现之后（统一时代）

一次开发，全部通用，任意模型接入，任意设备互通。

MCP服务器统一格式，统一报文，统一授权，统一传输

## 5.4 MCP 底层原理

1. 基于 JSON-RPC 2.0 标准；
2. 客户端、模型、MCP 服务器三方通信；
3. 标准化传输上下文、指令、文件、数据流
4. 自带权限隔离、安全管控



## 5.5 MCP、Skills、Function 三者层级关系

1. 底层： MCP（通信管道，通用接口）

   负责打通通路，能不能连接外部设备

2. 中层： Function(原子工具)

   管道里面最小工具

3. 上层：Skills(业务流程)

   工具组合成工作手册

   

总结： MCP 修路， Function 造工具，Skills 写使用手册

# 第六章 第五层周边依赖：自主智能层（Agent 智能体）

## 6.1 什么是Agent

Agent= 具备自主判断、自主规划、自动调用技能、自动执行任务的AI智能体

## 6.2 Agent 依赖哪些周边？

Agent必须依赖全套周边生态：

上下文+ Prompt +Function+ Skills+ MCP 

没有周边依赖，就没有Agent

## 6.3 Agent 运行步骤

1. 任务拆解
2. 自主选择技能
3. 通过MCP调用外部资源
4. 循环迭代直到完成

## 6.4 原生模型 VS Agent

1. 原生模型：被动回答
2. Agent智能体：主动干活

# 第七章 第六层周边依赖： 知识增强层（RAG知识库）



## 7.1 为什么需要RAG

大模型原生缺陷：

1. 知识截止；
2. 不懂私有资料；
3. 幻觉严重；
4. 不能读本地文件

## 7.2 RAG 完整流程

文档上传->切片->向量化-> 向量数据库->相似度检索->注入上下文->模型回答

## 7.3 RAG 定位

RAG是大模型的外挂硬盘

## 7.4 RAG 依赖组件

向量数据库，Embedding 嵌入模型，文档解析器, 切片器



# 第八章 第七层周边依赖： 生态应用层（插件，编排，工作台）

## 8.1 插件系统

##### 插件= 封装好的成品 Skills +Function  

普通用户一键安装，无需开发

例如： PDF插件、翻译插件、代码插件

## 8.2 工作流编排

把多个 Skills、插件、AI节点连城流水线，

例子：自动摘取资料->总结->排版->生成PPT

## 8.3 私有化部署周边

本地部署、量化压缩、蒸馏、微调、LoRA

# 第九章 全套层级

从低到高完整顺序（人类进化式升级）

1. 原生层： 单次对话（无记忆） 
2. 基础记忆层： 上下文窗口，上下文缓存 （让AI记得住）
3. 交互层： Prompt 提示词工程（让AI能听懂）
4. 原生工具层：Function Calling 函数调用（让AI有工具）
5. 流程封装层： Skills标准化技能（让AI会流程）
6. 通信协议层：MCP 通用传输协议（让AI通外界）
7. 自主执行层： Agent智能体（让AI自己干）
8. 知识外挂： RAG 向量知识库（让AI 有私库）
9. 成品生态层: 插件、工作流、私有化、应用部署 （让AI开箱即用）
